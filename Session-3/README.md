# Session 3 - DDD, Consistency, RTGS Middleware, and Containerization

Session 3 connects domain modeling, distributed-system consistency, banking middleware modernization, and container fundamentals.

## Materials

| File or Folder | Purpose |
|---|---|
| `Module-6_ DDD.pdf` | Domain Driven Design concepts and motivation. |
| `Module-9_ Consistency and Patterns.pdf` | Strong consistency, eventual consistency, and advanced architectural patterns. |
| `RTGS Middleware.pdf` | Current and future RTGS middleware thinking. |
| `Containerization_ Fundamnental.pdf` | Docker and containerization basics. |
| `DDD-Sample-codes/` | DDD-lite sample implementations for RTGS return management in Spring Boot and .NET. |

## What This Session Achieved

- Explained why business logic becomes hard to maintain when code turns into feature soup.
- Introduced DDD as a way to place business rules and business language at the center.
- Compared consistency models using banking-oriented examples.
- Used RTGS middleware as a practical context for modernization discussion.
- Introduced Dockerfile basics and container packaging concepts.
- Provided sample code that maps DDD-lite structure into real Spring Boot and .NET implementations.

## Key Message

Complex business systems need clear domain boundaries and deliberate consistency choices. Containerization then helps package those systems in a repeatable runtime form.
