# Session 5 - API Testing, Security Testing, and DevSecOps

Session 5 focuses on validating applications beyond simple unit tests and connecting security practices with delivery pipelines.

## Materials

| File | Purpose |
|---|---|
| `Module - 8_ Testing & Security.pdf` | API, integration, and security testing. |
| `Module - 11 and 17_ DevSecOps.pdf` | DevSecOps practices and secure delivery thinking. |

## What This Session Achieved

- Explained API testing strategies, including functional and contract testing.
- Connected integration testing with real system behavior and service boundaries.
- Introduced security testing as part of everyday development work.
- Discussed common secure coding risks such as trusting input too early.
- Positioned DevSecOps as a shared practice across development, QA, security, and operations.
- Prepared participants to understand security gates and scans inside modern pipelines.

## Key Message

Security and quality should be built into the delivery flow. DevSecOps is not a separate final review; it is a continuous engineering habit.
